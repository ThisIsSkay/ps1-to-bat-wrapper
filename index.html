How it works, the two methods & the exit-code contract

echo lines (ASCII)

Each line becomes one >>"%TMPPS1%" echo(… statement. % → %% everywhere, and & | < > ( ) ^ get a leading ^ outside double quotes. The tool re-parses each line the way cmd would and confirms it reconstructs the original, and the launcher counts the written lines to catch a partial write. Reliable for ASCII only, and a single line that (after escaping) nears cmd's ~8191-char command limit is rejected — use hybrid mode for those. Line endings are normalised to CRLF, so this mode is functionally faithful but not byte-for-byte.

self-read hybrid (UTF-8)

The body is stored byte-for-byte after a unique marker. The ASCII batch header launches PowerShell, which reads this file as UTF-8, extracts everything after the marker line (so leading/trailing blank lines are preserved), optionally checks its SHA-256, writes it to %TEMP% as a UTF-8 .ps1, and runs it with -File. cmd never parses the body, so non-ASCII survives and there is no per-line length limit. #requires, param() and arguments all work.

Save the hybrid .bat as UTF-8 without BOM (Notepad's default "UTF-8"). A BOM breaks cmd's first line. The temp .ps1 PowerShell writes gets a BOM on purpose, so Windows PowerShell 5.1 reads it as UTF-8. The script runs from %TEMP%, so $PSScriptRoot points there — the launcher also exports %BATDIR% as $env:LAUNCHER_DIR if your script needs its own location.

exit codes

CodeMeaning
0the script ran and returned 0
the script's own codepropagated verbatim when the script ran (e.g. exit 42 → 42)
201not elevated / UAC cancelled (script did not run)
202bad output location / UNC path (script did not run)
20364-bit Windows PowerShell not found (script did not run)
204embedded script could not be written or failed SHA-256 (script did not run)

Temp-cleanup failure is a warning only and never changes the exit code. A script that itself uses 201–204 is indistinguishable from the launcher's own — noted and accepted.

what SHA-256 does and doesn't do

It detects accidental corruption of the embedded script (bad copy, truncation, encoding damage). It is not a tamper-proof control: anyone who can edit the .bat can also change the embedded hash or turn the check off. For real authenticity, Authenticode-sign the script or the launcher.

both methods

Run in 64-bit powershell.exe even from a 32-bit prompt. The preview sandbox blocks saving .bat directly, so Copy is the reliable path: paste into Notepad, save as .bat (All files, UTF-8).

The launcher only writes, verifies, runs and deletes a copy of your script. Arguments you enter are inserted verbatim onto the PowerShell command line, so treat them as you would any command you'd run. Review any script before running it elevated.
