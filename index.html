How it works & the two methods

echo lines (ASCII)

Each line of your script becomes one >>"%TMPPS1%" echo(… statement, so the script stays readable in the .bat. Because cmd.exe treats some characters specially, they're rewritten: % → %% everywhere, and & | < > ( ) ^ get a leading ^ outside double quotes. The tool re-parses each line the way cmd would and confirms it reconstructs the original. The catch: echo emits bytes in the console code page, so this method is reliable for ASCII only — curly quotes, accents and box-drawing characters can corrupt.

self-read hybrid (UTF-8)

The script body is stored verbatim after a unique marker at the end of the file. The batch header (kept strictly ASCII) launches PowerShell, which reads this same file as UTF-8, extracts the body, optionally checks its SHA-256, writes it to %TEMP% as a UTF-8 .ps1, and runs it with -File. cmd never parses the body, so non-ASCII survives. Because it runs as a real file, #requires, param() blocks and launch arguments all work.

Save the hybrid .bat as UTF-8 without BOM. A BOM at the top breaks cmd's first line. Notepad's default "UTF-8" (not "UTF-8 with BOM") is correct; don't save as ANSI. The temp .ps1 that PowerShell writes gets a BOM on purpose, so Windows PowerShell 5.1 reads it as UTF-8.

One hybrid tradeoff: the script runs from %TEMP%, so $PSScriptRoot points there, not at the .bat folder. If your script needs its own location, pass it via the arguments field (e.g. -OutputBase "%~dp0out").

Both methods

Run in 64-bit powershell.exe even from a 32-bit prompt. The preview sandbox blocks saving .bat directly, so Copy is the reliable path: paste into Notepad, save as .bat (set "Save as type" to All files, encoding UTF-8).

The launcher only writes, verifies, runs and deletes a copy of your script — nothing more. Review any script before running it elevated. Exit codes: 0 ok · 1 not admin · 2 bad folder · 3 PowerShell missing · 4 write/verify failed · 5 script error · 6 temp delete failed.
